# ai-agent-mail

ИИ-агент для работы с почтой из мессенджера [Пачка](https://pachca.com).
Письма приходят карточками в чат; ответ пишет модель, но **отправляет только
человек** — после просмотра и правок.

## Что умеет

- уведомляет о новых письмах (поллинг IMAP раз в минуту);
- составляет черновик ответа, показывает его в треде и правит по вашим
  замечаниям («короче», «добавь про сроки») — сколько угодно раз;
- отправляет ответ с сохранением цепочки писем (`In-Reply-To` / `References`);
- пересылает письмо вместе с вложениями;
- удаляет письмо (с подтверждением) и убирает в архив.

## Архитектура

```
APScheduler ──(раз в 60 с)──► MCP: list_emails_metadata ──► IMAP
     │
     └──► Пачка: карточка письма + кнопки
                    ▲
Пачка ──события──► FastAPI ──► MCP: send_email / forward_email / delete_emails
```

Своего IMAP/SMTP-кода в проекте нет: вся работа с почтой идёт через
open-source MCP-сервер [`mcp-email-server`](https://github.com/Wh1isper/mcp-email-server)
(BSD-3-Clause). Он работает с любым ящиком по IMAP/SMTP.

**Модель не имеет инструментов.** Она возвращает только текст черновика;
`send_email`, `forward_email` и `delete_emails` вызывает сам бот после нажатия
кнопки человеком. Поэтому письмо не уйдёт и не удалится из-за галлюцинации
или инструкции, подброшенной в тело входящего письма.

### Как бот получает события

Два режима, переключаются переменной `EVENTS_MODE`:

| Режим | Когда нужен | Что требуется |
|---|---|---|
| `polling` (по умолчанию) | нет публичного адреса, локальный запуск, обкатка | включить «Сохранять историю событий» в настройках бота |
| `webhook` | рабочий VPS с доменом | домен, TLS, `PACHCA_SIGNING_SECRET` |

В режиме `polling` бот раз в 3 секунды читает журнал событий бота
(`GET /webhooks/events`) и удаляет прочитанное. Публичный HTTPS не нужен,
поэтому можно запускать даже с ноутбука.

## Установка

### 1. Конфигурация

```bash
cp .env.example .env
$EDITOR .env
```

### 2. Учётные данные ящика

Ящик задаётся переменными `MCP_EMAIL_SERVER_*` в том же `.env` — мастер с
браузером не нужен. Пример для Яндекса (нужен **пароль приложения**, а не
пароль от аккаунта):

```bash
MCP_EMAIL_SERVER_ACCOUNT_NAME=yandex        # должно совпадать с EMAIL_ACCOUNT
MCP_EMAIL_SERVER_EMAIL_ADDRESS=you@yandex.ru
MCP_EMAIL_SERVER_PASSWORD=пароль_приложения
MCP_EMAIL_SERVER_IMAP_HOST=imap.yandex.ru
MCP_EMAIL_SERVER_IMAP_PORT=993
MCP_EMAIL_SERVER_IMAP_SSL=true
MCP_EMAIL_SERVER_SMTP_HOST=smtp.yandex.ru
MCP_EMAIL_SERVER_SMTP_PORT=465
MCP_EMAIL_SERVER_SMTP_SSL=true
MCP_EMAIL_SERVER_SAVE_TO_SENT=true
```

Полный список — в `.env.example`. Проверить, что аккаунт виден:

```bash
docker compose exec bot mcp-email-server accounts list
```

### 3. Бот в Пачке

**Автоматизации → Интеграции → Чат-боты и Вебхуки → создать бота.**

- тип «Для одного чата», если ящик общий;
- скопировать токен в `PACHCA_TOKEN`;
- добавить бота в чат, id чата — в `PACHCA_CHANNEL_ID`;
- на вкладке «Исходящий Webhook» включить события **Новые сообщения** и
  **Нажатие кнопок**;
- для `EVENTS_MODE=polling` включить **«Сохранять историю событий»** и оставить
  Webhook URL пустым;
- для `EVENTS_MODE=webhook` указать `https://ВАШ_ДОМЕН/webhook` и скопировать
  Signing secret в `.env`;
- включить **«Игнорировать свои сообщения»**, чтобы бот не реагировал на себя.

### 4. Запуск

```bash
docker compose up -d --build
docker compose logs -f bot
```

В режиме `webhook` дополнительно поднимается Caddy с TLS:

```bash
docker compose --profile webhook up -d --build
```

Проверка живости: `curl localhost:8000/healthz`.

## Как этим пользоваться

1. Новое письмо → карточка в чате с кнопками
   **Ответить · Переслать · Полностью · В архив · Удалить**.
2. «Ответить» → под карточкой открывается тред с черновиком.
3. Любое ваше сообщение в треде — правка: бот перепишет и покажет заново.
4. «Отправить» — письмо уходит, кнопки гаснут.

Пересылка: нажать «Переслать», первым сообщением в треде написать адрес
получателя, вторым (по желанию) — комментарий.

## Переключение модели

```bash
LLM_PROVIDER=anthropic   # claude-haiku-4-5
LLM_PROVIDER=deepseek    # deepseek-chat, OpenAI-совместимый API
```

Остальной код про провайдера не знает: оба скрыты за `app/llm.py`. Если прямой
доступ к Anthropic закрыт, укажите `ANTHROPIC_BASE_URL` (или `HTTPS_PROXY`);
DeepSeek работает без прокси и годится как резерв.

## Первый запуск и дубли

- При первом старте бот не рассылает историю: запоминает текущий максимальный
  UID как точку отсчёта и сообщает только о письмах после неё.
- Ориентир — UID, а не флаг «непрочитано»: письмо, открытое в веб-интерфейсе
  раньше бота, всё равно попадёт в чат.
- Если провайдер пересоздал папку и UID обнулились, бот замечает это и
  сдвигает точку отсчёта, ничего не рассылая.
- Повторная доставка событий отсекается по ключу события, письма — по
  `Message-Id` и UID.

## Структура

| Файл | Назначение |
|---|---|
| `app/main.py` | FastAPI, планировщик, приём вебхуков |
| `app/poller.py` | поллинг почты, публикация карточек |
| `app/events.py` | чтение журнала событий (режим без публичного URL) |
| `app/handlers.py` | кнопки и правки черновиков в тредах |
| `app/llm.py` | Anthropic / DeepSeek за общим интерфейсом |
| `app/mail.py` | клиент MCP: единственное место, знающее о почте |
| `app/pachca.py` | REST-клиент Пачки с учётом лимитов |
| `app/cards.py` | тексты сообщений и раскладка кнопок |
| `app/db.py` | SQLite: точка поллинга, черновики, дедупликация |

## Лимиты, о которых стоит знать

- Пачка: ~4 сообщения в секунду на чат, 7500 сообщений в чат за сутки.
  При превышении отправка встаёт на час, каждая попытка в паузе удваивает её —
  бот выдерживает паузы по `Retry-After`.
- Кнопок в сообщении до 100, `data` кнопки до 255 символов.
- Удаление письма требует поддержки `UIDPLUS` на сервере (у Яндекса есть):
  удаляются только выбранные письма, без `EXPUNGE` на всю папку.
