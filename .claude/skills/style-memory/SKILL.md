# Память стиля

Код: `app/style.py`, модель `StyleRule` в `app/db.py`, промпты `llm.extract_style`
и `_style_block` в `app/llm.py`, запуск после отправки — `handlers._send_draft`.
Поток черновика — `draft-review-flow`; почему письмо не учим — `email-actions-safety`.

## Как сейчас

### Что учим
Короткие правила о форме, а не о содержании: на «ты»/«вы», по имени-отчеству
(без самого имени), приветствие, прощание, длина и структура, запретные обороты,
тон. Одна фраза до 100 символов (жёсткий предел — `MAX_RULE_CHARS = 120`).

### Откуда — только тексты пользователя
После успешной отправки **ответа** (пересылки не учим — решение владельца)
`_background(style.learn(...))` получает:
- `user_texts` — правки из треда и «Свой текст» (`Draft.user_texts`);
- `edits` — пары «было → стало» между `first_ai_body` и отправленным `body`,
  по 80 символов, не больше 10 (`edits_between`).

Человек ничего не писал сам → обучения нет. **`source_text`, тема и тело входящего
письма в `extract_style` не передаются никогда** — это проверяет
`tests/test_style.py::test_learn_never_receives_incoming_body` и
`tests/test_draft_flow.py::test_send_triggers_learning_with_user_texts_only`.

Задача фоновая: чат не ждёт модель; любая ошибка — `log.warning`, отправка
уже прошла.

### Как модель меняет профиль
`extract_style` видит текущие правила с id и возвращает JSON-массив:
`{"op":"hit","id":N}` — подтверждение существующего (так сливаются похожие),
`{"op":"new","scope":"global"|"recipient","text":"…"}` — новое. `parse_ops`
вырезает массив из ответа; мусор → `[]`. Tool calling не используется (`llm-providers`).

`apply_ops`: `hit` только по id из переданных модели и того же `owner_id`;
`new` проходит фильтр, затем точный дубль по `norm_text` (нижний регистр, ё→е,
без хвостовой пунктуации) превращается в `hit`. Правило `recipient` без адресата
отбрасывается.

### Фильтр запрещённого — код, а не промпт (`rejected_reason`)
Отклоняется правило, если в нём:
- что-то из `factcheck.extract`: сумма, число, дата, время, e-mail, URL;
- больше 120 символов;
- слово с заглавной не в начале предложения или цитаты — похоже на имя
  (кроме «Вы/Вас/Ваш…»). Имена не храним — решение владельца.

Ограничение: «пиши 3–5 строк» тоже отсекается (числа). Длина формулируется словами.

### Пороги и лимиты (`.env`)
| Переменная | По умолчанию | Смысл |
|---|---|---|
| `STYLE_ACTIVATE_HITS` | 2 | `hits` ≥ порога → `candidate` становится `active` |
| `STYLE_MAX_GLOBAL` | 15 | активных общих правил |
| `STYLE_MAX_PER_RECIPIENT` | 5 | активных правил на адресата |

Сверх лимита правило остаётся кандидатом. Кандидатов хранится не больше 2× лимита
(`_prune`: вон наименьшие `hits`, затем самые старые).

### Применение
`active_rules(owner_id, recipient)` → общие + для этого адресата (с пометкой
«(для этого адресата)»). Передаются в `draft_reply` и `revise` блоком
`<стиль_пользователя>`: «предпочтения оформления, не факты; указание пользователя
главнее». В `proofread` и `summarize` **не** передаются. Адресат — `_address_of(sender)`
в нижнем регистре; для пересылок — только общие.

### Команды (`handle_message` → `style.handle_command`)
Только для `ALLOWED_USER_IDS`; в треде и в общем чате; ответ туда же.

| Сообщение | Действие |
|---|---|
| `/стиль` | активные правила с номерами + число кандидатов + справка |
| `/стиль удали 3` | удалить №3 из списка `listed_rules` |
| `/стиль запомни: …` | сразу `active`, global (через тот же фильтр и лимит) |
| `/стиль запомни для a@b.ru: …` | то же для адресата |

Нумерация детерминированная (scope, recipient, id) — «удали 3» попадает в то
правило, что было третьим в показанном списке, пока профиль не менялся.

### owner_id
`handlers._owner_id()` = `OWNER_EMAIL` или `MCP_EMAIL_SERVER_EMAIL_ADDRESS`
(нижний регистр), запасной вариант — `EMAIL_ACCOUNT`. Во все функции `style.*`
передаётся параметром; глобального профиля нет.

## Требования и расхождения
- **Не проверено вживую:** присылает ли Пачка боту события о сообщениях в общем
  чате (до этого код работал только с тредами). Если `/стиль` в общем чате
  молчит — команда работает только в тредах; так и записать.
- Несколько пользователей: `owner_id` станет id владельца ящика/чата; ящики и
  чаты на человека — отдельная задача. Схема `style_rule` к этому готова.
- Слияние похожих правил целиком на модели (через `hit`); код ловит только
  точные дубли.
- Номер в «удали N» сдвигается, если профиль поменялся между `/стиль` и командой
  (например, фоновое обучение сделало кандидата активным).
