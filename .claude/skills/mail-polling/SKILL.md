# Поллинг почты

Код: `app/poller.py`, `PollState` / `TrackedEmail` в `app/db.py`, джоба в
`app/main.py`. Вызовы MCP — skill `mail-mcp`; вид карточки — `pachca-api`.

## Как сейчас

### Опрос, не IDLE
- APScheduler, джоба `poll_mail` каждые `POLL_INTERVAL=60` с,
  `max_instances=1, coalesce=True` (наложение циклов = дубли). Плюс `_lock`
  внутри `poll_once` — если проход ещё идёт, следующий пропускается.
- IMAP IDLE не используется: `mcp-email-server` 1.6.2 его не предоставляет
  (проверено по исходникам), а своего IMAP-кода у нас нет.

### Проход `poll_once`
1. `PollState(account, mailbox).last_uid` — докуда дочитали.
2. `mail.list_new(since_uid)` → письма с UID > last_uid (по возрастанию) и
   `top_uid` — максимум в первой странице (`POLL_PAGE_SIZE=50`, `order="desc"`).
3. **Первый запуск** (`last_uid == 0`): сохранить максимум, ничего не слать.
4. **Пересоздание папки**: новых нет и `top_uid < last_uid` → UID обнулились
   (сменился UIDVALIDITY), `_reset_uid(top_uid)` без рассылки.
5. Для каждого письма `_publish`, затем `_save_uid(uid)`; пауза 0,3 с.
   Ошибка публикации → `break`, UID не двигаем — повторим на следующем проходе.

Ориентир — UID, а не флаг «непрочитано»: письмо, открытое в веб-интерфейсе
раньше бота, всё равно попадёт в чат. `mark_as_read=False` при чтении тела.

### Дедупликация
- `TrackedEmail` с уникальными ключами `(account, mailbox, uid)` и
  `(account, rfc_message_id)`.
- До вставки — поиск по `Message-Id` (то же письмо с новым UID после переноса).
- Вставка строки = «заявка на публикацию»; `IntegrityError` → уже есть, пропуск.
- Карточку не удалось отправить → `_drop_claim(pk)` удаляет заявку (только если
  `pachca_message_id` пуст), иначе письмо навсегда спряталось бы дедупликацией.

### После рестарта
`last_uid` и `tracked_email` в SQLite на томе `bot-data` (`/data`) — рестарт
продолжает с той же точки, повторных карточек нет.

## Требования и расхождения
- Окно дублей: карточка отправлена, а процесс упал до `s.commit()` с
  `pachca_message_id` → при следующем проходе заявка останется без id, письмо
  пропустится по UID (строка есть) — но кнопки карточки будут ссылаться на запись
  без `pachca_message_id`, тред не создастся. Issue #3.
- Если новых писем больше `POLL_PAGE_SIZE` за интервал, старшие за пределами
  первой страницы не увидятся: `last_uid` сдвинется по видимым. Issue #2.
- `_save_uid` двигает точку только вперёд.
- Задержка уведомления — до `POLL_INTERVAL`. IDLE возможен только через замену
  или доработку MCP-сервера; решения нет.
