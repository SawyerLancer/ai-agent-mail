# Черновик → правка → подтверждение

Код: `app/handlers.py`, модель `Draft` в `app/db.py`, тексты и кнопки
`cards.draft_card` / `cards.draft_buttons`, промпты `llm.draft_reply` / `llm.revise` /
`llm.proofread`, проверка фактов `app/factcheck.py`, дифф вычитки `app/proofdiff.py`.
Профиль стиля в промптах — skill `style-memory`.
API тредов и кнопок — skill `pachca-api`; почему модель не отправляет сама —
`email-actions-safety`.

## Как сейчас

### Хранение
SQLite (`DB_PATH=/data/bot.sqlite3`), таблица `draft`:
`id, email_pk, thread_id, kind (reply|forward), status, body, recipients
(через запятую, для forward), preview_message_id, updated_at` и с этой версии:

| Поле | Что |
|---|---|
| `original_text` | «Свой текст» дословно — для «↩️ Без правок»; `_set_body` сбрасывает его при любом новом теле |
| `first_ai_body` | первый вариант ИИ (после «Заново» — новый): с ним сравнивается отправленное для `style-memory` |
| `source_text` | тело входящего письма, обрезанное до `BODY_CHARS_FOR_LLM`; источник для проверки фактов. **В обучение стилю не идёт** |
| `user_texts` | JSON: правки из треда и «Свой текст» |
| `added_facts` | JSON: что модель добавила от себя — строка «⚠️» в превью |

Колонки в старую базу добавляет `db._add_missing_columns()` при старте.
`preview_message_id` — последнее сообщение бота с кнопками черновика, у него
гасим кнопки при обновлении.

### Состояния
| Из | Событие | В |
|---|---|---|
| — | «Ответить» / «Переслать» | `editing` |
| `editing` | сообщение → `llm.revise`; «🔄 Заново» → `llm.draft_reply` | `editing` |
| `editing` | «✍️ Свой текст» | `awaiting_text` |
| `awaiting_text` | сообщение → `llm.proofread` | `editing` |
| `editing` | «↩️ Без правок» → `body = original_text` | `editing` |
| `editing` | «📨 Отправить» → `mail.send` / `mail.forward` | `sent` |
| `editing`, `awaiting_text` | «✖️ Отмена» | `cancelled` |
| `editing`, `awaiting_text` | без изменений `DRAFT_TTL_HOURS` | `expired` |

- Отправить/Заново/Свой текст на черновике не в `editing` → «_Черновик уже неактуален._».

### Ответ (`kind="reply"`)
1. `mail:reply:<pk>` → `_thread_for` находит/создаёт тред под карточкой.
2. «Готовлю черновик ответа…» → `llm.draft_reply` → `Draft(status="editing")`.
3. Превью с кнопками `📨 Отправить · ✍️ Свой текст` / `🔄 Заново · ✖️ Отмена`.
4. Сообщение в треде (`handle_message`) берёт последний открытый черновик треда
   (`_OPEN`). В `editing` текст уходит в `llm.revise` как **указание модели**
   (и копится в `user_texts`); в `awaiting_text` — идёт на вычитку (ниже).
   Сообщение `/стиль …` — команда памяти стиля, не правка.
   Старое превью → «_Черновик обновлён ниже._», новое — следующим сообщением.
5. «Отправить» → `mail.send(to=[адрес из From], subject="Re: …",
   in_reply_to=rfc_id, references=rfc_id)` → `status="sent"`, кнопки гаснут,
   в сообщении остаётся отправленный текст.

### Пересылка (`kind="forward"`)
1. `mail:fwd:<pk>` → черновик с `body="(без комментария)"`, вопрос «Кому переслать?».
2. Сообщение, похожее на адрес (`_looks_like_email`), → `recipients`.
3. Следующие сообщения идут в `llm.revise` как правка комментария.
4. «Отправить» без адреса → просьба указать адрес; иначе
   `mail.forward(uid, to, note=body)` с вложениями.

### Ошибки
Модель недоступна → сообщение в тред, черновик не меняется. Ошибка отправки →
«Отправить не удалось: …», статус остаётся `editing` — можно нажать снова.

### «✍️ Свой текст» — вычитка
- `draft:own:<id>` → `_ask_own_text`: черновик в `awaiting_text`, в тред
  `cards.own_text_prompt` с кнопкой «Отмена».
- Следующее сообщение → `_proofread_own`: `original_text` = текст как есть,
  `body = llm.proofread(текст)` — только орфография, пунктуация, согласование,
  опечатки. **Без профиля стиля и без `SIGNATURE`** (решение владельца).
  Модель недоступна → `body` = текст как есть, пометка «Проверить ошибки не удалось».
- Превью «**Ваш текст**»: что исправлено считает `proofdiff.compare` (difflib по
  словам), а не модель, — список `• _было_ → **стало**`, до 10 пунктов; одиночная
  пунктуация показывается вместе со словом перед ней. Без изменений —
  «_Ошибок не нашёл._».
- Затронуто > 30% слов **и** не меньше 3 слов (`ProofDiff.looks_rewritten`) →
  «⚠️ Модель изменила больше, чем ошибки». Второе условие нужно, потому что в
  тексте из трёх слов одна опечатка — это уже треть.
- «↩️ Без правок» (`draft:raw:<id>`) — только если вычитка что-то поменяла:
  `body = original_text`. Кнопки тогда `Отправить · Без правок · Свой текст` /
  `Заново · Отмена` — не больше трёх в ряд (`pachca-api`).

### Проверка добавленных фактов
После `draft_reply`, `revise`, `proofread` и «Без правок» `_set_body` вызывает
`factcheck.added(body, sources)`. Источники — `source_text`, `user_texts`,
`SIGNATURE`, тема и отправитель письма; **не** прошлый черновик, иначе
выдуманная однажды сумма после правки перестала бы помечаться. Чего нет в
источниках → «⚠️ Модель добавила: …». Отправку не блокирует.

Ищутся: суммы и числа (`150 000 ₽` = `150000 руб.` = `150 тыс.`; неразрывные
пробелы; `1,5 млн`), даты (`12.03.2026`, `12.03.26`, `12.03`, `2026-03-12`,
`01/04/2026`, «12 марта», «5-го мая 2026 года»; год сверяется, только если есть
в обоих текстах), время (`14:30`, `14.30 ч`, «в 9 часов»), e-mail, URL.
Нумерация списков `1.` / `2)` в начале строки фактом не считается.
Тесты — `tests/test_factcheck.py`.

### Срок жизни черновика
- `DRAFT_TTL_HOURS=48`. Джоба `expire_drafts` в планировщике раз в 10 минут
  переводит `_OPEN = ("editing", "awaiting_text")` со `updated_at` старше срока в
  `expired` и гасит кнопки превью: «_Черновик устарел — нажмите «Ответить» заново._».
- `updated_at` с `onupdate=_now`: срок считается от последнего изменения.
- Кнопка просроченного черновика → «_Черновик уже неактуален._».

## Требования и расхождения
- **Инвариант**: ни один путь кода не вызывает `send_email` / `forward_email`
  без нажатия `draft:send` человеком из `ALLOWED_USER_IDS`.
- Свой текст отправляется без подписи — решение владельца, не «забыли».
- Отправленный ответ (не пересылка) запускает обучение стиля фоновой задачей
  (`style.learn`), см. `style-memory`. Ошибка обучения на отправку не влияет.
- Повторное «Отправить» после ошибки таймаута MCP может отправить письмо дважды
  (см. `mail-mcp`).
