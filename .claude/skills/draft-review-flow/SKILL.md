# Черновик → правка → подтверждение

Код: `app/handlers.py`, модель `Draft` в `app/db.py`, тексты и кнопки
`cards.draft_card` / `cards.draft_buttons`, промпты `llm.draft_reply` / `llm.revise`.
API тредов и кнопок — skill `pachca-api`; почему модель не отправляет сама —
`email-actions-safety`.

## Как сейчас

### Хранение
SQLite (`DB_PATH=/data/bot.sqlite3`), таблица `draft`:
`id, email_pk, thread_id, kind (reply|forward), status, body, recipients
(через запятую, для forward), preview_message_id, updated_at`.
`preview_message_id` — последнее сообщение бота с кнопками черновика, у него
гасим кнопки при обновлении.

### Состояния
```
         ┌── сообщение в треде → llm.revise ──┐
         │   «🔄 Заново» → llm.draft_reply     │
         ▼                                    │
 [editing] ───────────────────────────────────┘
    │ «📨 Отправить»  → mail.send / mail.forward → [sent]
    │ «✖️ Отмена»                               → [cancelled]
```
- Отправить/Заново на черновике не в `editing` → «_Черновик уже неактуален._».
- **Таймаута нет**: черновик висит в `editing` бессрочно, никто его не закрывает.

### Ответ (`kind="reply"`)
1. `mail:reply:<pk>` → `_thread_for` находит/создаёт тред под карточкой.
2. «Готовлю черновик ответа…» → `llm.draft_reply` → `Draft(status="editing")`.
3. Превью с кнопками `📨 Отправить · 🔄 Заново · ✖️ Отмена`.
4. Любое сообщение в треде (`handle_message`) берёт последний `editing`-черновик
   этого треда и отправляет текст в `llm.revise` как **указание модели**.
   Старое превью → «_Черновик обновлён ниже._», новое — следующим сообщением.
5. «Отправить» → `mail.send(to=[адрес из From], subject="Re: …",
   in_reply_to=rfc_id, references=rfc_id)` → `status="sent"`, кнопки гаснут,
   в сообщении остаётся отправленный текст.

### Пересылка (`kind="forward"`)
1. `mail:fwd:<pk>` → черновик с `body="(без комментария)"`, вопрос «Кому переслать?».
2. Сообщение, похожее на адрес (`_looks_like_email`), → `recipients`.
3. Следующие сообщения идут в `llm.revise` как правка комментария.
4. «Отправить» без адреса → просьба указать адрес; иначе
   `mail.forward(uid, to, note=body)` с вложениями.

### Ошибки
Модель недоступна → сообщение в тред, черновик не меняется. Ошибка отправки →
«Отправить не удалось: …», статус остаётся `editing` — можно нажать снова.

## Требования и расхождения
### Инвариант
- Ни один: ни один путь кода не вызывает `send_email` / `forward_email`
  без нажатия `draft:send` человеком из `ALLOWED_USER_IDS`.
### Ручной текст — кнопка «✍️ Свой текст» (решено, не реализовано)
Расхождение с ТЗ: человек должен мочь отправить свой текст без переписывания
моделью. Сейчас любое сообщение уходит в `llm.revise`. Целевое поведение:
- Новая кнопка `BTN_OWN = "draft:own"` → `data="draft:own:<id>"` (лимит 255 не
  задевается: в `data` только id). Кнопок черновика становится 4 — раскладка в
  два ряда (`📨 Отправить · ✍️ Свой текст` / `🔄 Заново · ✖️ Отмена`), см.
  `pachca-api`.
- Нажатие → `status="awaiting_text"`, в тред: «Пришлите текст письма целиком —
  отправлю как есть, без правок модели».
- Следующее сообщение в треде при `awaiting_text` → `body` дословно (подпись
  `SIGNATURE` не добавляется — решение владельца), `status="editing"`, новое превью с
  кнопками. Модель не вызывается.
- «Отправить» по-прежнему обязательно — режим меняет только источник текста.
- `handle_message` ищет черновик в `editing` **или** `awaiting_text`.

### Уборка — срок жизни черновика (решено, не реализовано)
Сейчас таймаута нет: незакрытые `editing` копятся в SQLite, старые «Отправить»
живы бессрочно. Целевое поведение:
- Настройка `DRAFT_TTL_HOURS=48`.
- Джоба APScheduler (как `poll_mail`, `max_instances=1`) переводит черновики
  `editing`/`awaiting_text` со `updated_at` старше срока в `expired` и гасит
  кнопки у `preview_message_id`: «_Черновик устарел — нажмите «Ответить» заново._».
- `updated_at` обновлять при каждой правке (сейчас ставится только при создании).
- Нажатие на кнопку просроченного черновика → тот же ответ, что для неактуального.

Итоговые состояния: `editing ⇄ awaiting_text → sent | cancelled | expired`.

### Прочее
- Повторное «Отправить» после ошибки таймаута MCP может отправить письмо дважды
  (см. `mail-mcp`).
